# Deploying Arogyam Aradhya to Render

The whole app ships as **one Docker web service** (FastAPI serves both the API and the
built React app) plus a **managed PostgreSQL** database. One URL, no CORS, no separate
frontend host needed.

```
 ┌─────────────────────────────────────────┐
 │  Render Web Service (Docker)             │
 │   • FastAPI  →  /api/*                    │
 │   • React SPA →  everything else          │
 │   • product images → /static/*            │
 └───────────────┬─────────────────────────┘
                 │ DATABASE_URL
 ┌───────────────▼─────────────────────────┐
 │  Render PostgreSQL (managed)             │
 └─────────────────────────────────────────┘
```

## 1. Push to GitHub

```bash
cd D:/Arogyam_Aradhya
git add -A
git commit -m "Deploy setup"
git branch -M main
git remote add origin https://github.com/<you>/arogyam-aradhya.git
git push -u origin main
```

## 2. Create the services on Render (Blueprint)

1. Go to https://dashboard.render.com → **New +** → **Blueprint**.
2. Connect your GitHub repo. Render reads `render.yaml` and proposes:
   - a **PostgreSQL** database (`arogyam-db`)
   - a **web service** (`arogyam-aradhya`)
3. Click **Apply**. First build takes ~5–8 min (it builds the frontend, then the backend).

## 3. Set the admin password

In the web service → **Environment** → set **`ADMIN_PASSWORD`** to a strong value,
then **Save** (triggers a redeploy). `SECRET_KEY` is auto-generated by Render.

## 4. Open your site

`https://arogyam-aradhya.onrender.com`

- Store: `/`
- Admin: `/admin/login` (`admin` / the password you set)
- API docs: `/docs`

The database auto-creates its tables and seeds products + demo accounts on first boot.

---

## Important notes

- **Free tier sleeps.** The free web service spins down after ~15 min idle; the next
  request takes ~30–60 s to wake. Upgrade to a paid instance for always-on.
- **Free database expires** after 30 days. For anything real, use a paid Postgres plan
  (or another managed Postgres) and update `DATABASE_URL`.
- **Uploaded images don't persist.** The bundled product images (in the repo) are fine,
  but any image an admin *uploads* later lives on the container's ephemeral disk and is
  lost on redeploy. Before going live with uploads, wire in object storage
  (Cloudinary/S3). Ask and I'll add it.
- **Schema changes need care.** Tables are created with `create_all` (no migrations yet).
  Adding/removing columns later won't auto-apply to an existing DB — set up Alembic first
  (ask me) so you never lose data.
